# 6. DUPLICATION CONSISTENCY

Native Blender duplication should create a valid independent Beam projector.

Support:

- copy/paste
- Shift-D
- duplicate command
- Beam duplicate workflow

A duplicated projector must:

- receive the next PJ number
- receive a new UUID
- preserve technical settings
- preserve output mode
- preserve resolution
- preserve throw ratio
- preserve lens shift
- preserve brightness/lumens/stack
- remain independent
- not share mutable state in a way that causes cross-editing

It must also receive the **next study colour**, not copy the source colour.

# 15. BLEND GROUPS

Add a new Beam concept:

**Blend Group**

A Blend Group references multiple independent Beam projectors and provides group-level layout and overlap control.

Projectors must remain fully functional as individual Beam projectors.

Do not merge them into one object.

---

# 16. CREATE BLEND GROUP FROM ONE PROJECTOR

A user should not need to manually create all projectors first.

Workflow:

1. Select an existing projector, e.g. PJ01
2. Click `Create Blend Group`
3. Configure:
   - Layout
   - Projector count
   - Overlap
4. Beam creates the remaining projectors automatically

PJ01 becomes the first member / default anchor.

New projectors should inherit PJ01's technical settings:

- resolution
- throw ratio
- lens shift
- stack
- lumens
- brightness
- output mode

But each new projector must receive:

- new PJ number
- new UUID
- next study colour

---

# 18. CREATE BLEND GROUP FROM EXISTING PROJECTORS

# 19. GROUP ANCHOR

The first projector should act as the default anchor.

For example:

PJ01 remains fixed while group spacing/overlap is adjusted.

For a horizontal group:

PJ02 offset = 1 × spacing  
PJ03 offset = 2 × spacing  
PJ04 offset = 3 × spacing

Always calculate each member from the anchor and group spacing.

Do not chain-transform PJ03 from PJ02 etc.

This avoids accumulated errors.

---

# 20. UNIFORM BLEND SPACING

Add a group-level control for:

**Blend Overlap / Spacing**

Changing this value should move all projectors except the anchor uniformly.

For horizontal groups:

- adjust horizontal spacing

For vertical groups:

- adjust vertical spacing

For arrays:

- separate horizontal spacing
- separate vertical spacing

As the user changes overlap, projector positions should update live.

---

# 21. OVERLAP INPUTS

Allow overlap to be represented in:

- pixels

- physical distance

Show all three calculated values together.

Example:

Overlap:

`400 px`

`10.4%`

`1.84 m`

If practical, allow any one of these to be the editable input while the others update automatically.

---

# 22. ACTUAL VS DESIRED OVERLAP

Show:

- Desired Overlap
- Actual Overlap

Per adjacent projector pair.

Example:

PJ01 ↔ PJ02  
Desired: 400 px  
Actual: 397 px

PJ02 ↔ PJ03  
Desired: 400 px  
Actual: 405 px

This is especially useful after manual fine adjustments.

---

# 23. GROUP-LEVEL TRANSFORM

A Blend Group should have a parent/group controller.

Moving or rotating the group controller should move all member projectors together.

This should preserve:

- relative arrangement
- individual projector offsets
- group spacing logic

The Blend Group should behave like a parent transform layer.

---

# 24. INDIVIDUAL PROJECTOR CONTROL INSIDE A GROUP

Every member projector must still be directly editable.

The user must be able to adjust:

- position
- aim
- lens shift
- colour
- notes
- other projector settings

while it remains part of the Blend Group.

Use two transform layers conceptually:

## Group transform
Controls:

- overall position
- overall rotation
- uniform spacing
- overlap

## Projector local offset
Allows manual per-projector fine tuning.

The local offset should survive group movement.

---

# 25. RESET MEMBER TO GROUP POSITION

Add a per-projector action:

**Reset to Group Position**

This should remove the member's manual local positional adjustment and return it to the group's calculated ideal position.

Optional:

**Lock to Group Layout**

to prevent accidental local movement.

---

# 26. ALIGN / ASSIST BLEND

**Align Blend**

or:

Do not build a complex optimiser.

Use a clear deterministic layout based on projector raster geometry.
