# 1. FRUSTUM VISUAL TERMINATION

The visible projector frustum/cone helper currently continues too far through the scene.

Change the helper drawing behaviour.

For each visible frustum edge / corner ray:

- draw from the projector lens outward
- terminate the helper line at the first scene-geometry intersection
- if no geometry is hit, use a sensible fallback display distance

Important:

This is a **viewport helper change only**.

Do not change:

- actual projection behaviour
- multi-surface projection
- projection receivers
- occlusion
- centre-target logic
- engineering calculations

The real projection can still continue onto geometry where rays are unobstructed.

The helper cone should simply stop visually at first-hit geometry so it does not keep extending through walls/screens.

# 3. ADD SELECTED PROJECTOR

When adding an existing Beam projector to a Blend Group:

- preserve its current projector settings
- preserve its current transform
- preserve its UUID
- preserve its study colour
- do not automatically move it unless explicitly requested

After adding it:

- register it as a group member
- update member ordering
- update overlap calculations
- update group visualisation

Provide an explicit action such as:

**Align to Group**

or:

**Reflow Group**

if the user wants the new member moved into the calculated layout.

Do not silently reposition an existing projector.

---

# 4. ADD NEW PROJECTOR TO GROUP

`Add New Projector` should create a proper Beam projector using the same creation rules as the normal:

`+ Projector`

workflow.

The new projector must:

- receive the next PJ number
- receive a new UUID
- receive the next study colour
- inherit appropriate technical settings from the group/template projector
- be fully independent
- be added to the Blend Group
- be placed according to the current group layout where practical

---

# 5. REMOVE PROJECTOR FROM GROUP

Removing a projector from a Blend Group must:

- remove only the group relationship
- not delete the projector
- not change its UUID
- not reset its projector settings
- not move it unless explicitly requested

The projector should remain in the Blender scene as a valid independent Beam projector.

After removal:

- refresh group ordering
- refresh overlap calculations
- refresh spacing logic
- refresh visualisation

---

# 6. ANCHOR REMOVAL

If the current anchor projector is removed from a Blend Group:

handle this cleanly.

Preferred behaviour:

- automatically promote the next valid member to anchor

If this would create ambiguity, present a simple choice.

Do not leave the Blend Group in a broken state.

---

# 7. PROJECTORS DEFAULT TO LOCAL ORIENTATION

Beam projector manipulation should default to **Local orientation**.

The purpose is to make move/rotate controls intuitive relative to the projector itself.

Expected behaviour:

- yaw/pan rotates left/right relative to the projector
- pitch/tilt rotates up/down relative to the projector
- roll rotates around the optical axis
- movement along the projector axis feels natural
- projector controls should not unexpectedly follow World axes

Important:

Do not permanently force Blender's global transform orientation for the entire application.

Implement this in a way that makes Beam projectors intuitive while avoiding disruption to unrelated Blender objects/workflows.

All projectors created by:

- + Projector
- duplication
- copy/paste
- Blend Group creation
- Add New Projector

should follow the same local-orientation behaviour.

# 11. DUPLICATED PROJECTOR MEMBERS

When a Blend Group is duplicated, do not reuse the original member projectors.

Create new Beam projector objects.

Each duplicated projector must:

- receive the next study colour
- preserve source technical settings
- preserve resolution
- preserve throw ratio
- preserve lens shift
- preserve brightness
- preserve lumens
- preserve stack quantity
- preserve output mode
- preserve notes where appropriate
- remain fully independent

Do not share mutable data in a way that causes changes to the duplicate to modify the original.
