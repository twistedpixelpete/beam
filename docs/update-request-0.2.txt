# 1. ADD PIXEL SIZE

The add-on already calculates pixel density.

Add **Pixel Size** as a separate calculated value.

Definitions:

Pixel Density:
`pixels per metre`

Pixel Size:
`physical size of one projected pixel`

Calculate nominal pixel size from projected image width:

`Pixel Size = Image Width / Resolution X`

Display Pixel Size in:

`mm/px`

Example:

Image Width = 10 m  
Resolution X = 3840

Pixel Size ≈ 2.60 mm/px

Show both:

- Pixel Density: px/m
- Pixel Size: mm/px

Keep the calculation modular so later we can support separate horizontal and vertical pixel size if projection distortion is analysed.

# 4. STUDY VIEW EXPORT

Add an easy way to export the current working view.

There should be two concepts:

## A. Export Current View

Allow the user to export exactly what they are currently looking at in the 3D viewport as a study image.

Suggested operator:

`Export Current View`

This should be useful for quick ad-hoc study captures.

Where possible, preserve relevant overlays such as:

- projector labels
- frustums
- grids
- target visualisation

depending on current visibility settings.

---

## B. Saved Study Views

Allow users to create named repeatable study views based on Blender cameras.

Suggested workflow:

- user positions viewport
- presses `Create Study View From Current View`
- add-on creates or configures a Blender camera
- user names the study view

Examples:

- Overview
- PJ01 Coverage
- PJ02 Coverage
- Front Elevation
- Side Elevation
- Client View

Provide operators such as:

- Create Study View From Current View
- Export Selected Study View
- Export All Study Views

Each saved study view should have at minimum:

- view name
- camera reference
- export resolution

If practical, allow per-view settings for:

- include projector labels
- include frustums
- include grids
- include overlays

Keep this lightweight in this pass.

# 7. PERSISTENT ACTIVE PROJECTOR

This is an important workflow improvement.

Currently, projector details disappear when the user selects another piece of geometry.

Change this behaviour.

Introduce the concept of:

`Active Study Projector`

This must be independent of Blender's current selected object.

Workflow example:

1. Select PJ01
2. PJ01 becomes the Active Study Projector
3. Select a screen or venue object
4. Move the screen
5. Projection Study panel still displays PJ01
6. PJ01 values continue updating live as the target geometry moves

Selecting non-projector geometry must NOT clear the current Active Study Projector.

The panel should clearly show:

`Active Projector: PJ01`

Provide a way to change it, such as:

- dropdown
- `Use Selected Projector`
- pin button
- clear button

Recommended behaviour:

When a projector is selected, automatically set it as the Active Study Projector.

After that, keep it active until:

- another projector is chosen
- user explicitly clears it

This allows users to manipulate screens, surfaces and venue geometry while continuously monitoring projector calculations.

---

# 8. LIVE UPDATE WHEN TARGET GEOMETRY MOVES

Ensure calculated projector values update not only when the projector moves, but also when relevant target geometry moves.

At minimum update:

- throw distance
- target centre
- image width
- image height
- pixel density
- pixel size
- DPI
- illuminance

when:

- projector transform changes
- target object transform changes

Do this efficiently.

Avoid expensive full-scene recalculation on every dependency graph update.

Only update affected projectors where practical.
