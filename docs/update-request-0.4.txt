# 1. TRUE PROJECTOR BEHAVIOUR

The projection must behave like a real projector.

The key distinction is:

**Target = centre-ray reference for calculations**

**Projection receivers = any geometry intersecting the projector frustum**

These must remain separate concepts.

## Automatic centre target

Do not require manual target assignment during normal use.

Cast a ray from the projector lens through the exact centre of the projector raster.

The **first scene geometry hit by this centre ray** becomes the current projector target.

Automatically determine:

- target object
- target point
- target X/Y/Z
- target distance

Recalculate whenever:

- projector moves
- projector rotates
- relevant geometry moves

If the centre ray hits nothing:

- show `No Target`
- do not retain stale target values
- do not display misleading zero calculations
- keep the projection frustum visible

The target is a calculation reference only.

It must never act as a clipping plane.

---

# 2. ANY GEOMETRY IN THE RASTER RECEIVES PROJECTION

Any scene geometry entering the projector raster/frustum should immediately receive the appropriate portion of the projected image.

The object must not need to be:

- the centre target
- selected
- manually assigned
- tagged as a screen
- registered as a receiver

If geometry intersects any part of the projector frustum, it should receive projection automatically.

Example:

- centre raster hits a screen at 10 m
- left edge misses the screen
- left edge continues
- left edge hits a wall at 15 m

Expected result:

- screen receives the centre area of the raster
- wall receives the correct left portion
- image remains one continuous perspective projection

---

# 3. OCCLUSION

Projection must respect line-of-sight.

Foreground geometry should block only the rays it physically intercepts.

If a foreground object blocks part of the raster:

- the foreground object receives that part
- geometry behind it should not receive those blocked rays

However:

- rays passing beside the object continue farther
- those rays may hit geometry behind it

Do not stop the whole projection because one object or the centre ray was hit.

---

# 4. CONTINUOUS IMAGE COORDINATES

The projected raster must remain spatially continuous across multiple surfaces and depths.

Do not restart, stretch, refit, or remap the image separately per object.

The same projector raster must drive all receiving geometry.

This applies to all output modes.

Moving geometry through the frustum should reveal the appropriate portion of the same image.

---

# 5. REALTIME PROJECTION

Realtime viewport behaviour is a hard requirement.

When:

- projector moves
- projector rotates
- geometry moves into the beam
- geometry moves out of the beam
- geometry crosses the centre ray

the following should update immediately or close to realtime:

- visible projection
- target object
- target point
- throw distance
- image width
- image height
- pixel density
- pixel size
- DPI
- illuminance
- labels

Normal study work must not require rendering after every change.

Use an efficient EEVEE / GPU / viewport-friendly method where practical.

Do not brute-force raycast every projector pixel in Python.

# 6. PERSISTENT ACTIVE PROJECTOR

The Projection Study panel should not disappear or change just because the user selects ordinary geometry.

Introduce:

**Active Study Projector**

Workflow:

1. Select PJ01
2. PJ01 becomes active
3. Select a screen or wall
4. Move that geometry
5. PJ01 data remains visible
6. PJ01 calculations continue updating

Selecting non-projector geometry must not clear the active projector.

When another projector is selected, that projector becomes active.

Provide:

- Active Projector display
- dropdown if practical
- `Use Selected Projector`
- clear/pin option if useful

# 7. PIXEL SIZE

Add **Pixel Size** alongside Pixel Density.

Pixel Density:

`px/m`

Pixel Size:

`mm/px`

Formula:

`Pixel Size = Image Width / Resolution X`

Example:

Image width = 10 m  
Resolution = 3840 px

Pixel size ≈ 2.60 mm/px

Display both:

- Pixel Density
- Pixel Size

Keep the calculation modular for possible future horizontal/vertical pixel-size analysis.

# 9. PROJECTOR DUPLICATION MUST FEEL NATIVE

Copying, pasting, duplicating, or Shift-D duplicating a projector in Blender must produce the same logical result as using the add-on’s `+ Projector` button.

A duplicated projector must:

- receive the next available PJ name
- receive a new UUID
- preserve the source projector’s technical settings
- preserve resolution
- preserve throw ratio
- preserve lens shift
- preserve brightness
- preserve lumens
- preserve stack quantity
- preserve output mode
- preserve all valid projector settings
- remain fully independent
- not share mutable internal data in a way that links changes between projectors

In addition:

**the duplicated projector must receive the next study colour in the soft palette**, not inherit the source colour.

Example:

PJ02 duplicated  
→ PJ03  
→ new UUID  
→ same technical settings  
→ next available study colour

Manual colour override remains possible afterward.
